# PCL.MemoryOptimizer

PCL-HE 的随身内存优化组件：在**不终止任何进程**的前提下，把物理内存里暂时用不上的页面交还给系统，让可用内存立刻上升。

> **已实测可用 · 不保证完全无问题**
> 本组件在 Windows 10/11 上经过实测（数据见下），但它直接调用未公开文档的内核接口，
> 不同系统版本、不同内存压力下的表现可能有差异。**使用前请读完「已知风险」一节，后果自负。**

## 三种档位

| 档位 | 做什么 | 需要管理员 | 影响范围 |
| --- | --- | --- | --- |
| **轻量护航**（`RunGuarded`） | 整理**本进程**的工作集 | 否 | 只有调用者自己 |
| **游戏内护航**（`RunGameBoost`） | 把游戏进程的内存优先级提到 `MEMORY_PRIORITY_NORMAL`，再逐个 `EmptyWorkingSet` 其它进程，游戏 PID 全程排除 | 否 | 能打开的进程，**绝不包含游戏** |
| **深度清理**（`RunDeepSystemWide`） | 执行内核命令 `NtSetSystemInformation(SystemMemoryListInformation = 80, MemoryEmptyWorkingSets = 2)`：把**全系统**的工作集页一次性移出物理内存 | 是 | 所有进程——**没有任何排除参数** |
| 逐进程清理（`RunDeepPerProcess`） | 底层能力：遍历进程逐个 `EmptyWorkingSet`，可跳过指定 PID；游戏内护航在它之上 | 否（同用户进程） | 能打开的进程 |

三档的取舍：轻量护航零打扰但收益也小（只动启动器自己）；深度清理收益最大但会连同游戏一起清空，游戏紧接着要重读资源；**游戏内护航是游戏运行中的选择**——游戏一个字节都不动，被清的是浏览器、聊天软件、编辑器这些后台程序。

## 实测数据

Windows 11 / 16 GB 物理内存 / 非管理员会话改用提权子进程执行，`MemoryEmptyWorkingSets` 单次调用：

| 指标 | 数值 |
| --- | --- |
| 可用物理内存 | 6.97 GB → 9.43 GB（**约 +2.4 GB**） |
| 命令耗时 | 664 ms |
| 进程数 | 267 → 267（**一个没少**） |
| 全部进程工作集总和 | 6.28 GB → 0.44 GB → 2.64 GB → 3.14 GB（28 秒内自然回升） |
| 已修改页列表峰值 | 112 MB → **4.50 GB**（约 28 秒自行消化完） |

游戏内护航（`RunGameBoost`，非管理员，自检时人为限制为只处理 5 个进程以降低干扰）：

| 指标 | 数值 |
| --- | --- |
| `SetProcessInformation(ProcessMemoryPriorityInformation)` | 对目标进程返回 `TRUE` |
| 处理进程 / 跳过 / 失败 | 5 / 114 / 0 |
| 工作集减少（仅 5 个进程） | 44 MB |
| 耗时 | 22 ms |
| 进程数 | 289 → 289（不变） |

对照：原版 PCL2 在同一台机器上报告「可用内存增加了 3.05 G」，量级一致。

## 已知风险

- **执行瞬间所有程序的内存页都被移出物理内存**（深度清理），之后首次访问它们会稍慢：SSD 上是毫秒级，机械硬盘上体感明显。干净的映射页无需写盘，已修改页需要写回页面文件或被内存压缩。
- 因此**不要在游戏运行时执行深度清理**——游戏的工作集同样会被一刀切走，之后加载新区域或资源会明显卡顿。要动后台又不动游戏，用**游戏内护航**。
- 被清出工作集的程序切回前台时会有一次短暂迟滞（页面要重新读回），这是正常代价，不是故障。
- 不建议高频使用。内存压力过去后系统自己也会回收这些页面。
- 本组件**不终止、不挂起、不修改**任何进程，也不改动任何文件。

## 权限

- 深度清理：`SeProfileSingleProcessPrivilege` 与 `SeIncreaseQuotaPrivilege` 必须在令牌中**显式启用**（默认在管理员令牌里也是禁用状态）。
- 逐进程与游戏内护航：只需要 `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_SET_QUOTA`（打开进程）与 `PROCESS_SET_INFORMATION`（设置内存优先级），同用户进程即可，不需要管理员。
- 提权执行由调用方（PCL-HE）通过其提权子进程通道完成；本类库只负责启用特权并调用内核接口，不做静默提权。
- 未启用特权时内核返回 `STATUS_PRIVILEGE_NOT_HELD (0xC0000061)`，本类库会如实报错，不假装成功。

## 它不是什么

- 它**不增加**系统可用内存的「总量」：被移出的页本来就是可立即回收的资源；清空**待机列表**（命令 4）也不会让可用内存变多——Windows 的口径是 `可用 = 空闲 + 零页 + 待机`。
- 它的真实收益是**在内存吃紧时把压力从物理内存挪到页面文件与内存压缩**，代价是之后的一次访问变慢。
- 内存优先级只影响「谁先被换出」，不改变任何进程能用的内存上限。

## 来源与依据

- 命令编号来自 Sysinternals RAMMap 的 Empty 菜单与社区逆向结果（`NtSetSystemInformation` 信息类 80）。
- 内存优先级：`SetProcessInformation` 的 `ProcessMemoryPriorityInformation`（0）与 `MEMORY_PRIORITY_NORMAL`（5），Windows 8 起提供。
- 同类实现参考：PCL-CE 曾在 `MemSwapService` 中使用同款内核调用，后于 v2.15.0-beta.3 移除（理由：枚举未文档化、SSD 额外写入）。
- 微软口径：PDC 2010《Mysteries of Windows Memory Management Revealed》——`Available = zero + free + standby`。
